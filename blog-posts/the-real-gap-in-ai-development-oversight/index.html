The Real Gap in AI Development: Oversight

Writing better prompts is the easy part. The harder problem is safely integrating probabilistic AI systems into deterministic engineering workflows.

Nathan Tebay · May 2026

Most of what I hear about AI these days is just people trying to write better prompts.

What actually matters to me is oversight.

The real risks aren't about compilation

The real risks with AI-generated code have nothing to do with whether it compiles.

  • Unsafe operations
  • Hidden assumptions
  • Over-delegation
  • Lack of validation
  • Unclear escalation paths
  • Loss of architectural control

The question has changed

The hard part isn't what it used to be. "How do I get AI to generate more code?" Now the question is different.

"How do I safely integrate probabilistic systems into deterministic workflows?"

With traditional software, the same input gives you the same output every time. AI doesn't work like that. Oversight and validation aren't optional. They have to be there from the start.

Ground rules for oversight

On my projects, I set some ground rules:

  • AI-generated code could never write directly to disk.
  • Static analysis blocked unsafe patterns before review.
  • Confidence thresholds determined when work goes back to human review.
  • Security-sensitive tasks are never delegated.
  • Revision loops were capped to prevent unbounded correction cycles.

I put those checks in place because AI isn't predictable. AI can do a lot, but it's inconsistent in ways traditional software isn't.

The problem isn't usually syntax. It's that AI can produce code that looks fine but quietly breaks your assumptions, your security, or your architecture.

Build systems that don't require trust

That turns the whole engineering problem on its head.

The answer isn't to trust the model more. The answer is to build systems that don't require you to trust the model. Validation, escalation, and containment need to be built in from the start.

Thinking this way changed how I handle incremental delivery too. On several projects, I broke work into phases with clear review points before moving forward — not because AI can't generate big batches of code, but because it's easier to check small, isolated changes.

Where experience still matters

This is where experienced engineers still have a real edge when working with AI.

The difficult part is no longer generating code. The hard part now is designing systems where you can actually evaluate generated code safely and predictably.

AI made it cheaper to crank out code. It didn't make it any easier to know if that code should exist at all.
