Overview

QMK Nexus is a full-stack web app for building custom keyboard firmware without hand-editing QMK source files. The frontend guides users through the key design stages: physical layout, matrix wiring, peripheral setup, keymap editing, metadata, feature toggles, and firmware build.

The backend stores user keyboards, checks build readiness, generates QMK-compatible C and header files, and runs firmware builds inside an isolated Podman builder. It also includes a QMK keyboard index so existing boards can be loaded or adapted.

Challenges

  • Translating a visual keyboard layout into valid QMK matrix definitions, keymap files, config headers, rules files, and layout macros.
  • Keeping frontend camelCase models and backend Python models synchronized without leaking serialization details into every API endpoint.
  • Building a layout editor that supports key placement, selection, resizing, rotation, matrix assignment, and peripheral placement while staying predictable.
  • Running firmware builds safely from a web request by isolating QMK compilation inside a short-lived builder container or build proxy.
  • Supporting QMK-native imports alongside generated keyboards without promising unsupported MCU and feature combinations.

Learnings

  • Firmware generators need snapshot tests. Small formatting or macro changes can silently break generated C even when the web workflow still looks correct.
  • Visual editors need a strict data model. It is easier to render from normalized keyboard data than to infer firmware structure from canvas state after the fact.
  • Build status should be treated as durable application state, not a process-local dictionary, once builds may outlive a single backend worker.
  • Feature support should be explicit in both the UI and backend validation so the build button cannot become the first place a user discovers an unsupported target.

Key Systems

  • Layout editor - React Konva canvas for key geometry, matrix wiring, peripheral placement, selection, and transform controls.
  • Keymap editor - layer manager, keycode picker, encoder mapping, OLED configuration, and feature-specific controls.
  • Code generation - emits QMK source files for config.h, rules.mk, keymap.c, keyboard.c, and keyboard headers.
  • Build pipeline - FastAPI route prepares a build directory, delegates to an ECS Fargate build service (or local Podman in dev), polls status, and serves compiled artifacts.
  • Persistence - per-user SQLite database on S3; no shared database. Local SQLite file in development.
  • QMK index - generated keyboard metadata and conversion scripts for browsing and importing supported keyboard definitions.

Current Scope

  • Authenticated web app with Google OAuth 2.0; per-user storage with up to 20 saved keyboards.
  • AVR and ARM builds: atmega32u4/u2, at90usb1286, atmega328p, STM32F072/F103/F303, mk20dx256, RP2040.
  • Generated firmware path and QMK-native source import path for upstream keyboards.
  • Visual layout editor — drag, resize, rotate keys; ISO enter; multi-select with transform.
  • Matrix wiring canvas with Union-Find row/col derivation; encoder, OLED, and trackball support.
  • Full QMK keycode library; unlimited layers; OLED configurator with preset and custom C blocks.
  • 15 feature modules: RGB Matrix, RGB Light, Backlight, Split, Encoder, OLED, Pointing Device, Tap Dance, Combo, Mouse Keys, NKRO, Boot Magic, Console, Extra Keys, Audio.
  • Import from 1000+ keyboards in the QMK index; custom source file overrides.
  • Live build log with 2s polling and one-click firmware download.
