PersonalSite

This site — a personal portfolio and documentation platform built from scratch with vanilla HTML, CSS, and JavaScript

View on GitHub

Overview

For this project I decided to utilize Claude Code as much as possible in designing, implementing, and documenting my personal website. I had several requirements in mind:

  • Use no frameworks, libraries, or build tools — just plain HTML, CSS, and JavaScript
  • Host the site on AWS Lambda using a container that could be hosted for free within the AWS Free Tier limits
  • Implement a simple CMS for blog posts and links as lightweight as possible.
  • Ensure the site was performant and responsive, with a good user experience on both desktop and mobile devices.
  • Utilize AI as much as possible in the development and documentation process.

This approach allowed me to get familiar with Claude Code while creating a highly optimized personal website. I would not have implemented this with CGI, as I haven't used it before. However, I am very happy with the result, as it is clean, fast, and perfectly meets my needs. I'm not sure Claude Code saved much time, but it allowed me to take a different approach and produced a less bloated codebase than a framework would have. It also eased some interactions with AWS, largely by taking me out of the console and resulting in an automated deployment script. Overall, this was a fun and rewarding project that I'm happy with, and it was a great way to learn more about web development and AI-assisted coding. I also learned a lot about the limitations and gotchas of AWS Lambda, which was a valuable experience in itself.

Stack

HTML5 CSS3 Vanilla JS Shell / CGI BusyBox httpd AWS Lambda AWS S3 CloudFront Podman

Challenges

  • Lambda's read-only filesystem requires copying the web root to /tmp/www at startup — symlinks and bind mounts don't work here.
  • MinIO client silently fails with STS temporary credentials — replaced with AWS CLI, adding ~100 MB to the image.
  • 128 MB Lambda = 1/16th vCPU — AWS CLI Python startup hit the 30s timeout. 512 MB fixed it.
  • Synchronous S3 sync in the entrypoint blocked httpd startup. Moved before exec and raised AWS_LWA_READINESS_CHECK_TIMEOUT.
  • grep on the manifest preserves leading commas, producing invalid JSON — fixed with sed 's/^,*//' before inserting.

Learnings

  • Lambda + CGI is a natural fit — one invocation per request, stateless by default. Cold-start S3 sync is the main drawback.
  • Lambda's 6 MB payload limit breaks video delivery — serve via S3/CloudFront instead.
  • Claude Code works well for frontend, CGI scripts, Dockerfiles, and AWS setup. It struggled with BusyBox httpd vs Apache, CGI path conventions, and simple auth — required coaching and tended to leave refactoring remnants.
  • Third-party S3 clients may silently drop STS credentials — AWS CLI is the only safe choice inside Lambda.
  • Lambda CPU is strictly proportional to allocated memory. Inadequate memory manifests as slow Python startup, not OOM errors — making it look like a network or timeout bug.
  • Ship placeholder manifests in the image — copied to /tmp on startup, they prevent blank pages if the S3 sync is slow.

Key Features

  • Shared layout script injects nav/header — no build step, consistent across all pages.
  • Multi-theme colour picker with WCAG contrast, persisted to localStorage.
  • Blog with draft/publish workflow, WIP placeholders, and per-post image uploads.
  • Categorised links page managed via the same admin CMS as the blog.
  • Cookie-based session auth for the admin panel.
  • POSIX shell CGI scripts — no Node, no PHP, no runtime beyond AWS CLI and Lambda Web Adapter.
  • S3-backed local cache for zero-latency reads.
  • Full S3 sync on cold start prevents blank pages on first request.
