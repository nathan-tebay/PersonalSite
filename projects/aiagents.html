AI Agents

Modular local AI agent system for scraping, market analysis, coding assistance, scheduling, review, and long-term memory

View on GitHub

Overview

AI Agents is a Python-based orchestration project for running a small team of focused local agents. Claude Code acts as the planner and reviewer while a configured LM Studio model handles worker tasks through an OpenAI-compatible API. The goal is to keep high-level architecture and approvals with Claude while offloading bounded scraping, market analysis, and small coding jobs to local models.

The system centers on an OrchestratorAgent that dispatches work to specialized agents, a TaskRouter that decides when coding tasks are safe to delegate, and a CodeReviewer gate that prevents generated code from being written without review. Shared memory gives every agent a common place to store facts, task history, context, and semantic recall across sessions.

Stack

Python AsyncIO Pydantic LM Studio OpenAI-compatible API SQLite ChromaDB APScheduler Playwright BeautifulSoup yfinance pytest

Key Systems

  • Orchestration - starts shared services, schedules recurring jobs, dispatches tasks, tracks retries, and keeps agent execution consistent.
  • Coding delegation - routes small and medium coding tasks through CodingAgent, applies safety checks, and requires review before any write-to-disk step.
  • Scraping workflow - uses Playwright or BeautifulSoup to collect page content, then summarizes and structures results with the configured worker model.
  • Market workflow - pulls ticker data and news signals, then produces scheduled analysis reports for tracked symbols.
  • Shared memory - combines structured SQLite records with ChromaDB semantic search so agents can recall task outcomes, preferences, and prior context.

Challenges

  • Drawing a hard boundary between work a local model can safely produce and work Claude should handle directly, especially for security-sensitive or broad multi-file changes.
  • Making delegated code generation useful without ever treating it as automatically trusted output.
  • Keeping the memory layer centralized so agents share context without reaching into database internals.
  • Designing schedules, retries, and logging so long-running worker tasks can fail clearly instead of silently disappearing.

Learnings

  • A local model is most useful when the task boundary is narrow, the expected output format is typed, and a reviewer gate is mandatory.
  • Agent memory needs both durable structured records and fuzzy semantic search; one without the other misses important operational context.
  • Coding agents need policy in configuration, not scattered conditionals, so delegation rules can evolve as the system is tested.
  • The simplest orchestration system is often easier to trust: explicit agents, explicit routes, explicit review, and plain logs beat hidden framework magic.

Current Scope

  • On-demand scraping and coding tasks.
  • Scheduled stock analysis and orchestrator health checks.
  • SQLite development storage with optional PostgreSQL path.
  • ChromaDB semantic memory for recall across sessions.
  • Systemd service files and helper scripts for local startup.
