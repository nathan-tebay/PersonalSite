Fly Fishing Game

16-bit style 2D fly fishing simulation set on the Madison River, Montana — built in Godot 4

View on GitHub
Work in progress. River generation at beta; working on other visual elements and gameplay.

Overview

A 16-bit pixel art fly fishing game grounded in realistic angling principles: hatch-driven fish behaviour, directional fish vision cones, edge feeding philosophy, and skill-based casting with a false-cast rhythm system. The river cross-section is side-scrolling, showing depth layers from surface film to riverbed, with fish holding in hydraulic pockets behind boulders and in eddies.

The river is procedurally generated from a seed using FastNoiseLite depth profiles, rock and boulder placement, eddy currents, island generation, and a hold-scoring algorithm that identifies the prime feeding lies. A depth-field rendering pipeline blends tile colours through a multi-stop gradient with two passes of box blur, rock bow-wave and wake zones, and caustic sparkle in shallows. Three difficulty tiers (Arcade, Standard, Sim) tune spook radii, fish counts, and fly-matching strictness through a single DifficultyConfig resource.

Initial scope targets the Mother's Day Caddis hatch on a single river section, with the hatch cycle driving fish feeding mode from subsurface emergers to surface dry flies.

Challenges

  • Procedural river generation that produces realistic hydraulics — depth profiles, holding lies, eddy currents, and boulder wake zones — from a single integer seed.
  • Rendering a depth-field river cross-section with smooth colour transitions, rock disturbance zones, and caustic sparkle using only Godot's 2D drawing API (no shaders for the base terrain).
  • Implementing fish spook logic that respects directional vision cones, approach angle, wading vibration, shadow projection, and cast quality — all routed through a single SpookCalculator to prevent divergence.
  • Designing a casting state machine with false-cast rhythm, line-length timing scaling, and mend detection that feels skill-expressive without being obtuse.
  • Streaming infinite procedural river sections seamlessly while preserving fish state, angler position, and camera limits across section boundaries.

Learnings

  • Centralising all spook radius calculations in one module (SpookCalculator) early paid off — difficulty tuning and new spook sources could be added without touching AI or movement code.
  • Godot's _draw() API is capable of complex terrain rendering but requires careful batching into Sprite2D chunks to avoid per-frame redraw cost on large maps.
  • Separating river data generation (RiverGenerator) from rendering (RiverRenderer) made it possible to unit-test hold scoring and section streaming logic independently of the visual layer.
  • Planning sessions documented as GDD sections before implementation prevented scope creep and gave a stable reference when revisiting systems after weeks away from the codebase.

Key Systems

  • RiverGenerator — depth profile via FastNoiseLite → tile map → current map → structure placement → eddy currents → hold scoring → top holds, seeded deterministically
  • RiverRenderer — continuous depth-field pipeline: blur passes, rock wake zones, current lightening, Sprite2D chunk baking, and wake seam Line2D overlays
  • CastingController — state machine IDLE → FALSE_CASTING → PRESENTATION → RESULT → DRIFT, with line-length timing scaling and mouse mend detection
  • SpookCalculator — all spook radius checks route here; formula accounts for fish size, cover, time of day, approach angle, and difficulty tier
  • FishAI — FEEDING → ALERT → SPOOKED → RELOCATING → HOLDING state machine driven by SpookCalculator and FlyMatcher rejection events
  • HatchManager — time-of-day hatch state machine shifts fish feeding mode between emerger and dry fly windows; drives FlyMatcher best-match fly
  • DatabaseManager — autoload; opens user://flyfishing.db on startup, runs schema migrations, seeds difficulty presets; all persistence routes here
  • Section streaming — pre-generates next section at 70% through current; despawns two sections behind; seed chain derived from session seed + section index
